## 2. Что уже сильно

1. **Есть явный daily hook.** `GET /api/miniapp/retention/home` + claim `POST .../daily-film/claim`: стабильный фильм/сериал дня на MSK-день, +15 монет, персонализация по жанрам из оценок ≥6 и пулу популярного unseen. На UI — блок над выкладками (`#home-retention-root` выше `#home-dashboard-root`).

2. **Ачивки связаны с возвратом.** Серия `streak_2`…`streak_30`, progress на главной («Вы уже близко»), toast после действия, celebration/TG notify. Комментарий в коде верный по смыслу: streak должен отражать «день с кино», не пустой визит.

3. **Выкладки архитектурно зрелые.** Shell `dashboard?lite=1` + `/api/home/rails/*`, постеры через `fast_poster_url_for_list`, кэш, empty CTA для unwatched/series. Недавний баг «retention перерисовал и снёс rails» (#534) починен — отдельный root, не `innerHTML` dashboard.

4. **Есть внешние касания.** Четверговый/выходной push с персонализацией, reengage при ≥14 днях тишины не чаще раза в 45 дней, plan reminders, buzz digest, achievement TG. Это не пустой inbox.

5. **Power-user контент на главной есть.** Планы, премьеры, турнир, непросмотренное, сериалы — база для привычки «открыл → что дальше» уже лежит в продукте, не в маркетинге.

## 3. Что слабо / ломает D1–D7

### 3.1. Нет цепочки D1 → D2 → D3

Между «онбординг закончен» и «четверговый weekend push» почти пусто.

- Отдельных пушей/TG/email «завтра фильм дня», «остался 1 день до streak_3», «вы не открыли рекомендацию» в коде нет.
- Reengage стартует с **14 дней** — для D1/D7 это уже опоздание: человек ушёл на этапе привычки.
- Film-of-day живёт только inside-app: не claim’нул — никто не напомнил.

Итог: механика daily есть, **петли возврата снаружи почти нет**.

### 3.2. Streak размыт визитом на главную

В `PERSONAL_ACHIEVEMENTS_DEF` написано: streak растёт от полезного действия.  
Но `miniapp_retention_home` вызывает `check_and_update_streak(uid)` при простой загрузке retention на `/home`.

Эффект: открыл главную (даже чтобы глянуть монеты) = день стрика + `COINS_STREAK_DAILY` (30). Ачивки «Первый возврат» / «Кинонеделя» дешевеют. У Никиты за день 2026-09-20 внезапно закрылись `streak_2` и `streak_3` — похоже на запуск этой ветки, не на новую кино-привычку.

### 3.3. Фильм дня — слабый «крючок», сильный «клик»

Сейчас до claim: блюр/locked poster, текст «Откройте рекомендацию на сегодня», +15 монет. После — открыть карточку.

Проблемы:

- +15 монет на фоне старта 500 / импорта 2000 / стрика 30 — почти шум.
- Claim **не** кладёт фильм в «Посмотреть», **не** предлагает план на вечер, **не** пишет «напомните в 20:00».
- Для библиотеки из 484 unwatched персональный pick из «популярного, чего нет у вас» легко ощущается как случайный Netflix-рандом, а не «это именно вам сегодня».
- Нет связи «открыл → посмотрел/оценил → streak» в одном сценарии. Цепочка рвётся на карточке фильма.

### 3.4. Выкладки ≠ habit loop

Rails хороши как **инвентарь** (непросмотренное, оценки, сериалы, премьеры). Они плохо создают **ежедневный ритуал**.

- Нет одного «главного действия дня» кроме фильма дня.
- Нет «продолжи сериал с незакрытой серии» как первой карточки.
- Нет вечернего режима «что смотреть сегодня из ваших 484».
- Empty state осмыслен только у unwatched/series; recent-rated/premieres при пустоте молчат.

Для новичка с пустой базой главная может выглядеть пустовато + retention goal. Для Никиты — длинная лента без приоритета.

### 3.5. Дизайн ачивок

- Имена друзей: `friends_5`…`friends_50` все с названием «Не имей ста рублей» — в UI плохо отличимы.
- Много volume-лестниц (films/ratings) без эмоциональной награды «за вкус / за план с другом / за досмотр сериала в срок».
- `CELEBRATION_ACHIEVEMENT_IDS` = по сути **все** ачивки после 2026-09-19 → риск спама попапами/тостами у активных.
- Для Никиты «следующие награды» скачут к далёким тирам (`streak_7`, `ratings_1000`) — progress bar 990/1000 ок, но `streak_7` при текущей логике визита либо фармится впустую, либо сбрасывается реальной жизнью без кино-действий.

### 3.6. Монеты не подпирают daily

Earn много, sink узкий (Shazam 100, постер 150, random 30, билет 35…). Daily +15 не создаёт дефицита и не тянет в продукт завтра. Монета не объясняет «зачем возвращаться», только «получил циферку».

### 3.7. Социальный контур профиля хромает (гость)

`/api/public/user/301810276` отвечает нормально (OG: «Никита — 990 оценок…»).  
В браузере гостя: `html.mp-user-boot`, `#landing` скрыт, но `#section-user` остаётся `.hidden` с текстом «← Назад» — профиль визуально не собирается. Шаринг ачивок/профиля как retention/viral петля сейчас слабый.

### 3.8. Риск спама (не daily, а weekend)

Четверг (кино/шазам/сериалы/дом/микс/buzz) + выходные + plan push + achievement DM. Частота reengage адекватная (45 дней). Риск не в daily-спаме (его нет), а в том, что **шумный weekend** придёт к тем, кто так и не получил аккуратный D2 «вернись за фильмом дня».

## 4. Приоритетные рекомендации

### P0 — сделать сразу (удержание D1–D3)

1. **Убрать `check_and_update_streak` из `GET /retention/home`.** Streak только из rate / add / episode / plan / cinema / claim фильма дня (осмысленное действие). Иначе ачивки врут.
2. **D2 nudge (один канал на выбор: TG или push):** если D1 был (онбординг/claim/оценка), а D2 тишина к 18–20 MSK — одно короткое сообщение: «Фильм дня ещё не открыт» / «До „Вошёл во вкус“ остался 1 день» + deep link на `/home`. Не чаще 1 раза.
3. **После claim фильма дня — один CTA:** «В „Посмотреть“» + «Запланировать сегодня вечером». Без этого daily = клик ради монет.
4. **Починить гостевой `/u/:id`:** section-user должен краситься из public API (сейчас boot ломается). Иначе профиль Никиты и шаринг ачивок не работают как витрина.

### P1 — усилить петлю за 1–2 недели

5. **Персональный «вечерний» rail:** 6–8 карточек из unwatched, отсортированных под вкус (как daily pool), заголовок «На сегодня из вашей базы». Это превращает 484 хвоста в действие.
6. **Связать film-of-day ↔ streak явно в UI:** «Откройте и отметьте/оцените — день серии засчитается». Сейчас пользователь не понимает правила.
7. **D3/D7 soft touch:** только если есть незакрытый progress (`streak_3` / `streak_7` remaining ≤2) — иначе молчать. Копирайт уже есть в `ach.reason.streak_*`.
8. **Монеты daily:** либо поднять награду и показать sink («хватит на Shazam»), либо заменить настуюку «бесплатный Shazam/рандом раз в день» — иначе +15 бессмысленны.
9. **Ачивки:** разные имена для friends_*; не показывать celebration на каждую common volume-ступень (оставить rare+ и streak/social).

### P2 — эксперименты и продукт дальше

10. A/B: mystery claim vs сразу название+жанр на карточке дня (гипотеза: доверие важнее интриги).
11. A/B: позиция retention-блока — над rails vs между «планы» и «непросмотренное».
12. Сериал дня: если у пользователя есть series-in-progress — приоритет «следующая серия», а не новый тайтл из каталога.
13. Метрики (обязательно завести, если ещё нет): claim rate, D1→D2 return, D1→D7, % открытий `/home` с claim, streak_7 earn rate после фикса visit-streak, unsubscribe/block после D2 nudge.

## 5. Следующие эксперименты (конкретно)

| # | Эксперимент | Успех за 7–14 дней |
|---|-------------|-------------------|
| E1 | Streak только от полезного действия | `streak_3` earn rate ↓ но D7 quality ↑ (доля с оценкой/эпизодом в день стрика) |
| E2 | TG/push D2 «фильм дня не открыт» на когорте новых | D2 return +X п.п., block rate < 1% |
| E3 | Claim → add to watchlist default on | доля «посмотрел/оценил daily film за 7 дней» |
| E4 | Rail «На сегодня из вашей базы» | CTR в карточку vs unwatched rail |
| E5 | Celebration только rare+ | жалобы/закрытия попапа ↓, retention без изменения |

Не деплоить всё сразу: E1+E2 дают максимум ясности по D1/D7 при минимальном UI.

## 6. Краткий вердикт

Сделано правильное направление: daily film + progress ачивок + rails + отдельный retention root.  
Для D1/D7 этого **мало**: нет внешнего возврата на день 2–3, стрик портится визитом, claim не переводит в просмотр/план, выкладки не приоритизируют «сегодня», профиль для гостя не собирается.  
Для аккаунта Никиты текущий блок больше витрина механики, чем личный ритуал — удержание power user упрётся в «сегодня из моей базы» + сериалы + планы, а не в онбординг-goal.
